UI Design System

How the game's interface looks, reads and behaves. Every specimen below is drawn by the game's own stylesheets and modules (src/ui/theme/), so this page cannot drift from the game. The rest of the design lives in the design bible.

Principles

What every screen has to serve.

The world comes first. The HUD keeps to the edges and windows dock to the sides, so the middle of the screen is always play. The map is the one window that takes over.
One look. Parchment cards in dark wood frames with brass rivets, burgundy for buttons and titles, gold for the one main action, pixel icons for things. No new colours outside theme.css.
Every action three ways. Mouse, keyboard and controller can all do everything a window offers. A window open on a controller takes the pad; with a mouse you can keep walking.
Scaled, not reflowed. The UI is laid out on a virtual screen 1029 px tall and scaled to the window (scale.ts), times the player's UI Size setting. Sizes in the CSS are those virtual pixels.
Never in the way. Nothing covers another part of the HUD at 1280×720 or 1920×1080, and no browser shortcut steals a game key (Ctrl is crouch: Ctrl+key presses are kept from the browser).
Show what the server says. Online, windows show the island the server keeps. Commands go to the server; the window redraws when its answer arrives (the same tick).

Writing

Labels name things; sentences explain them. They are capitalised differently.

Sentence Case for Sentences

What people say, quest stories and objectives, descriptions, notes, errors and toasts are sentences: a capital to start, the rest as written.

“The bench is yours whenever you've the goods.”
Carry a pack here and press F to sell.
Place your scarecrow on open, level ground.
Not enough money

Try It

titleCase() and isTitleCase() in src/ui/theme/text.ts; tests/ui.spec.ts opens the game's windows and checks their labels with it.

Also

  • Call things what the world calls them: Labor, Seals, Packs, the Windspire. Names keep their own capitals.
  • Numbers and units: 52 m, 3s, 12 km/h, 80%. Keys are drawn as key caps: F Esc.
  • Never type in capitals; the type line of a tooltip and the place banner are set in capitals by CSS.
  • Something still happening ends in an ellipsis: Saving…, Reconnecting…
  • Giving something up asks once more (Abandon → Give it up?). Nothing is ever lost to one click.

Layout

Where everything lives on screen. Windows dock to the sides; the map takes the centre.

Things drawn over the world (name plates, damage numbers, the target plate) live outside the UI root and scale themselves by --ui-s. Tooltips and context menus are drawn in the UI root, beside the pointer, kept on screen.

Components

Build new UI from these; they are the game's own classes.

Buttons

One gold button per window, for its main action (Accept, Complete Quest, Place). Burgundy for the rest. Disabled buttons stay visible, greyed, with the reason nearby or in the tooltip. Text in a button is nudged down by --cap-nudge, because Pagella's capitals sit 0.115em above the middle of their line; anything that centres text in a box uses it.

Windows

A wood frame, a title strip (title, then a short subtitle), a close button, a scrolling body (a drawn scrollbar and fade when it overflows) and a foot holding the actions. Someone you talk to looks out of a portrait medallion over the top left corner; the body starts below it. The main window docks left, the bag docks right.

Interaction

The same moves do the same things everywhere.

Items

  • Hover: the tooltip (what it is, what it's worth).
  • Click: picks it out (highlight).
  • Double-click: its main action. Place a scarecrow, plant a seed, equip a glider, summon a vehicle, use a tonic. With a merchant's window open, sell it; with your chest open, store it.
  • Right-click: a menu of everything you can do with it right now, the main action first and in bold; anything you can't do here is greyed out with why.

Controller and Keys

  • D-pad or arrows move the highlight over a window's buttons and items.
  • A (Enter): press it; on an item, its main action.
  • Y: an item's menu. B (Esc): back out.
  • Esc closes the topmost thing first: a menu, then the window, then the bag, then cancels placing.
  • A window that belongs to someone closes when you walk away from them.

Checklist for New UI

  • Labels in Title Case, sentences in sentence case (isTitleCase, and tests/ui.spec.ts covers the windows it opens).
  • Built from .mw, .lui-btn, .ib, .tt, .ctx and the colour variables; no one-off colours.
  • One gold button at most, for the main action.
  • Works with mouse, keyboard and controller; Esc and B back out.
  • Sized in virtual pixels inside #ui; looked at in a screenshot at 1280×720 and 1920×1080 with nothing overlapping.
  • Items: click picks, double-click does the main thing, right-click lists the rest.
  • Shows the server's word online; never changes the world from the UI (it queues commands).
